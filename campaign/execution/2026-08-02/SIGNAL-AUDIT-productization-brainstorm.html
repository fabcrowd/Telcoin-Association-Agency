02What the dashboard renders

The core finding

The collection layer is well ahead of the visualization layer. Two panels — Narrative Ledger and Open Questions — are already spec'd to unlock at day 1, which has passed, and the fully-compiled RAW data array sits correct and audit-ready in the page's own <script> tag. None of it renders a single pixel. Today the artifact shows a progress bar and a hand-written paragraph of numbers — not one chart is data-driven yet. That's simultaneously the weakest thing about the current build (there's nothing to demo) and the cheapest lever available (wiring up two panels needs zero new data collection, only a template over data that already exists).

03Productizing it — four tracks

Assuming the buyer is a crypto project (a DAO, an L1, an exchange-listed token, a DeFi protocol) that wants to track its own social presence the way this was built to track Telcoin's. Grouped by what unlocks each: template work against data already collected, a real API budget, or a new product surface entirely.

Wire up what's already collected

low effort
  • Render Narrative Ledger and Open Questions now — both panels are gated on data that already exists in every JSON file
  • Turn the inert RAW array into an actual two-point line, even below the 14-day threshold — shade it to signal "too few points for a trend" rather than hiding it entirely
  • Surface share_of_voice as a real indexed chart against competitors, not just numbers embedded in a paragraph

Zero new scraping. This is pure template work against data the pipeline already produces — the fastest way to make a demo actually look like a product.

Replace WebSearch with real APIs

high effort
  • X API and Reddit API (praw) in place of site-search scraping — unlocks real timestamps (a live hour-of-day heat map instead of 100% "unknown"), real engagement metrics (likes/reposts as an actual influence weight), and real follower counts (tell a whale's post from a bot's)
  • A paid news API (GDELT, NewsAPI) replaces the "Telcoin" broad-search workaround with genuine date filtering
  • Historical query on these APIs finally makes a real backfill possible — the honest zero-result backfill this pipeline hit is a WebSearch ceiling, not a permanent one

This is the single highest-leverage change and the main thing separating an internal script from a paid product. It's also the main cost line in any pricing model — API access, not engineering time, becomes the marginal cost per client.

Turn passive tracking into alerts

medium effort
  • The question ledger already tracks times_observed and status — push a Slack/email alert when an open question crosses a threshold, converting "we noticed" into "someone should answer this today"
  • Sentiment-swing alerts: notify when a day's score moves outside its recent range, sized by n so a 3-post spike can't trigger it
  • Narrative-surge detection: a subject climbing fast against its own baseline, not against an arbitrary fixed threshold

Dashboards get checked when someone remembers to. Alerts are what justify a recurring subscription instead of a one-time report.

Multi-tenant & portfolio view

medium effort
  • The taxonomy is already a swappable JSON file per client — the architecture for "your own narrative categories" already exists, it just needs a config layer instead of one hardcoded file
  • An exchange or fund wants several tickers side by side — the per-narrative, per-platform breakdown generalizes to a multi-asset grid with no schema change
  • White-label the dashboard's CSS tokens per client brand — the whole page is already built on custom properties

The path from "one internal tool" to "N paying clients" runs through configuration, not a rewrite — the schema was accidentally built tenant-ready.

04The actual wedge

LunarCrush, Santiment, and The Tie already sell crypto social sentiment. Competing on data volume alone loses — they have direct firehose access this pipeline doesn't. The differentiated pitch is what happens on the other side of the number.

Incumbent pattern

A single blended score, 0–100 or similar. Confidence, sample size, and method are not shown. A client cannot tell whether "62" came from 3 posts or 30,000, or trace it back to a single source post.

This pipeline's pattern

Every number carries its tier (measured / observed / derived / unavailable) and, where relevant, its sample size. A 0.53 sentiment score is never shown without its n. Zero results are reported as zero, not smoothed into a chart. Every aggregate traces back to the individual posts that produced it.

Where this actually sells

Institutions that face regulatory or governance exposure — DAOs answerable to a council, banks, associations with a constitution — cannot act on a vibe score they can't defend. The taxonomy's publishable: false flag, the question ledger's audit trail, and the tier system exist because this pipeline was built for exactly that kind of organization. That's not a generic feature list; it's a vertical — social intelligence for on-chain governance orgs, not "another crypto Twitter dashboard."
